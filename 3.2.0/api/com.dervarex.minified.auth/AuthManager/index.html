login()

staticSource
public static User login()
Starts the device-code login flow and blocks until the login completes.

While this method is running, the device verification URL and user code are published to the shared loginState as soon as they are issued by the provider. This allows a UI thread to call getLoginState() (or getLoginStateJson()) and display the URL/code before login() returns.

Typical use: call startDeviceCodeLoginAsync() from UI code and poll the state. Use this blocking method only in special cases where a background thread is guaranteed, and you explicitly want a synchronous result.

Example: 

new Thread(AuthManager::login).start();
while (true) {
LoginState state = AuthManager.getLoginState();
if (state.userCode != null && state.verificationUri != null) {
System.out.println(state.verificationUri + " -> " + state.userCode);
break;
}
try { Thread.sleep(100); } catch (InterruptedException ignored) {}
}
Returns
User

startDeviceCodeLoginAsync()

staticexperimentalSource
public static String startDeviceCodeLoginAsync()
Starts the device-code login flow on a background thread and returns immediately.

Typical use: call this from UI code, then poll getLoginState() (or JSON) to show the verification URL and user code while the login is pending. Use login() only in special cases where a synchronous, blocking call on a dedicated background thread is preferred.

Returns
StringThe initial login state as JSON, usually STARTING or PENDING
