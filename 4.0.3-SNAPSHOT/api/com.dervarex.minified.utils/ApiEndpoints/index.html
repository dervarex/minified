VERSION_MANIFEST_URL

staticSource
public static final String VERSION_MANIFEST_URL = "https://launchermeta.mojang.com/mc/game/version_manifest_v2.json"
The Vanilla Version Manifest.
Every version of Minecraft since rd-132211 is listed here.

Example of how one entry looks like in the version manifest: 

{
  "id": "26.4-snapshot-7",
  "type": "snapshot",
  "url": "https://piston-meta.mojang.com/v1/packages/6be84ec668c4c843c87f80f2a8efa3095f2989d2/26.4-snapshot-7.json",
  "time": "2026-11-03T13:18:26+00:00",
  "releaseTime": "2026-11-03T13:08:56+00:00",
  "sha1": "6be84ec668c4c843c87f80f2a8efa3095f2989d2",
  "complianceLevel": 1
}
As you can see, the url field contains another URL.
This is the "version json", it contains the arguments required for launching the game,
the assetIndex which contains an url to the assets' metadata,
the downloads for client and server JAR downloads, the list of libraries needed,
which version of java it wants and a few more essentials like the mainClass.

RESOURCES_URL

staticSource
public static final String RESOURCES_URL = "https://resources.download.minecraft.net/"
This is the resources base url.

The hashes come from the assetIndex in the version JSON, the needed files can be fetched by appending the subdirectory (first two characters of the hash), "/" and the hash of the asset.

Example: https://resources.download.minecraft.net/10/1058cf72714c48b154e7883cb9d7ec918e0816b3 - cave1.ogg

There you'll get a file named after the hash, not after what it actually is. You need the assets' metadata again, since this is the only source where the real name is linked to the hash, in this case, minecraft/sounds/ambient/cave/cave1.ogg to 1058cf72714c48b154e7883cb9d7ec918e0816b3

NEOFORGE_INSTALLER_BASE_URL

staticSource
public static final String NEOFORGE_INSTALLER_BASE_URL = "https://maven.neoforged.net/releases/net/neoforged/neoforge/"
File Host for all Neoforge Loaders. One subdirectory is one Loader Version (beta versions get their own ones too).
Every of those Files has hashes: md5, sha1, sha256 and sha512.

Changelog

  • neoforge-20.4.167-changelog.txt Changelog for the Loader Version
  • ...changelog.txt.asc PGP Signature for the Changelog

Installer

  • neoforge-20.4.167-installer.jar the neoforge installer jar
  • ...installer.jar.asc PGP Signature for the Installer

POM (Maven)

  • neoforge-20.4.167.pom maven pom file
  • ...pom.asc PGP Signature for the pom file

Sources

  • neoforge-20.4.167-sources.jar neoforge sources jar
  • ...sources.jar.asc PGP Signature for the sources jar

Universal

  • neoforge-20.4.167-universal.jar universal installer for neoforge
  • ...universal.jar.asc PGP Signature for the universal installer

UserDev

  • neoforge-20.4.167-userdev.jar dev kit containing access transformers, patches, and joined Minecraft sources for modding
  • ...userdev.jar.asc PGP Signature for the dev kit

Dev Kit Explanation:

Inside the userdev.jar it looks about like this:

  • ats - Access Transformers. These files change the visibility (access) of Minecraft classes and methods so mods can access them
  • META-INF - Manifest data, usually not a lot
  • patches - The NeoForge source patches. These are human-readable unified diffs that modify vanilla Minecraft classes. They add Neoforge features, hooks and APIs.
  • config.json - Configuration file for the dev environment setup
  • joined.lzma - An LZMA compressed file. It contains the binary patches (.binpatch). The Gradle plugin decompresses this automatically in the background during project sync/import, please don't try to do it yourself ;)

Why .lzma and not .zip?
LZMA compresses a lot better than .zip, especially in already compressed archives (.jar is an archive already!)
